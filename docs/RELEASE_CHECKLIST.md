# GameArchiveManager 0.1.0 RC 发布检查清单

> 2026-08-28 的实际证据归并与剩余发布动作见 [`RELEASE_AUDIT_2026-08-28.md`](RELEASE_AUDIT_2026-08-28.md)。本文件保留可重复执行的逐项模板；未机械回填的方框不应覆盖审计报告、自动化、VM 证据或 `project_state.json` 的实际状态。

本清单用于当前 Release Candidate 的发布门禁验收。带 `[ ]` 的项目必须由发布人员逐项确认；不要因为自动测试通过就跳过真实压缩包、真实 Windows 文件系统和磁盘安全测试。当前仍是 RC，不代表正式 Release。

## 1. 环境检查

- [ ] 在目标 Windows 10 或 Windows 11 机器上完成测试。
- [ ] 源码运行环境执行 `py --version`，确认 Python 3.10 或更高版本可用；Portable RC 构建在无 Python 的干净 VM 中也必须能启动。
- [ ] 在项目根目录执行 `py main.py`，或启动 RC 构建，确认显示 `0.1.0 / Release Candidate`。
- [ ] 分别验证无工具、只有 7-Zip、只有 WinRAR、只有 LZ4 和全工具环境；工具缺失必须可解释而不是崩溃。
- [ ] 确认 ToolManager 按显式配置、项目 `tools` 目录及一级子目录、常见安装路径、Windows PATH 的顺序发现并验证工具。
- [ ] 确认 `requirements.txt` 为空，项目没有意外增加第三方 Python 依赖。
- [ ] 使用无 7-Zip 的测试环境验证程序返回 `TOOL_NOT_FOUND`，而不是崩溃。

## 2. 基础功能测试

### 自动测试

- [ ] 执行完整测试：

  ```powershell
  py -B -m unittest discover -s tests -v
  ```

- [ ] 确认所有测试通过，没有 `FAILED` 或 `ERROR`。当前治理基线为至少 224 项测试；任何 skip 必须记录外部工具或环境原因。
- [ ] 确认普通 ZIP 真实 7-Zip 解压测试通过；如果显示 `skipped`，必须先安装 7-Zip 后重新运行。
- [ ] 确认伪装 ZIP（例如扩展名为 `.mp4`）能够根据文件头识别为 ZIP。

### 人工测试

- [ ] 使用不含敏感数据的普通 ZIP，确认可以解压并生成独立输出目录。
- [ ] 使用不含密码的真实 RAR，确认 7-Zip 可以解压。
- [ ] 使用不含密码的真实 7Z，确认 7-Zip 可以解压。
- [ ] 使用扩展名与真实格式不一致的测试文件，确认报告显示真实格式和伪装状态。
- [ ] 同一输入重复运行至少三次，确认使用安全唯一输出目录（`_2`、`_3` 等），旧目录没有被覆盖。
- [ ] 确认原始 ZIP、RAR、7Z 文件均保持存在且内容未改变。

说明：Mocked Adapter 测试不能替代真实工具测试。RC 必须在工具可用的 Windows 环境验证普通 ZIP/RAR/7Z、LZ4、RAR.LZ4、分卷以及嵌入归档流程。

## 3. 密码测试

- [ ] 准备一个合法的加密测试压缩包，不使用个人或生产密码。
- [ ] 创建名称为测试密码的真实空文件夹，确认 Scanner 将其记录为密码候选。
- [ ] 确认普通文件名不会进入密码候选。
- [ ] 确认首次解压返回 `PASSWORD_REQUIRED` 后才进入密码恢复流程。
- [ ] 确认错误候选返回 `WRONG_PASSWORD` 并继续尝试下一个候选。
- [ ] 确认正确候选成功后立即停止尝试。
- [ ] 确认尝试次数不超过 `max_password_attempts`，并且绝对不超过 100。
- [ ] 检查任务日志、历史 JSON 和 TaskReport，确认没有测试密码明文。
- [ ] 确认程序没有创建持久密码数据库；成功密码只允许保留在当前进程的 SessionPasswordStore，退出后消失。

说明：当前自动测试包含模拟及环境允许时的真实工具覆盖；真实加密 RAR/7Z 仍必须在 RC Windows 环境人工验证。

## 4. 递归测试

- [ ] 准备安全的小型测试链：`game.zip → data.rar → patch.7z`。
- [ ] 确认初始压缩包深度为 0，后续压缩包深度依次增加。
- [ ] 确认每层完成后由 ArchiveFinder 发现下一层，而不是一次性无边界解压。
- [ ] 确认重复路径不会被重复加入同一 Pipeline。
- [ ] 降低 `max_recursive_depth`，确认超过深度的任务不会加入队列。
- [ ] 降低 `max_archive_tasks`，确认超过数量的任务不会加入队列。
- [ ] 明确启用对应 ignore 设置后，在嵌套输出中加入 `Android`、独立 `AZ` token、`安卓` 路径，确认相应压缩包被记录为跳过且没有解压；默认设置不得过滤平台内容。
- [ ] 确认 PipelineResult 保存执行记录、父压缩包、深度、输出路径和递归跳过记录。

说明：每个初始压缩包拥有独立 Pipeline，因此递归深度和任务数量限制按初始压缩包分别计算。

## 5. 安全测试

### 解压前

- [ ] 设置较小的 `max_archive_size_mb`，确认超限压缩包不会进入 Extractor。
- [ ] 使用 ZIP 测试文件确认能够统计内部文件数量和预计解压大小。
- [ ] 使用包含 `../`、绝对路径或 Windows 驱动器路径的受控 ZIP，确认执行计划被阻断。
- [ ] 设置 `max_extracted_files` 和 `max_total_extracted_size_mb`，确认 ZIP 预计值超限时不执行解压。

### 解压后

- [ ] 确认输出目录不存在时安全检查返回失败。
- [ ] 确认实际文件数量超限时 Coordinator 将结果标记为失败。
- [ ] 确认实际总大小超限时 Coordinator 将结果标记为失败。
- [ ] 确认解压后检查不跟随目录符号链接。
- [ ] 确认安全失败后不会自动删除输出，便于用户检查。

### 清理

- [ ] CleanupManager 扫描后、调用 `delete()` 前，所有候选目录和文件保持存在。
- [ ] 自动成功清理只作用于 RuntimeTracker 记录的本次运行拥有目录；不得按 `_extracted` 名称删除未知历史目录。
- [ ] 超时、取消、异常和交付待选择时保留内部目录并记录 `ORPHANED_TEMP`。
- [ ] 确认只能删除本次扫描或 `authorize_owned()` 明确授权的候选目录。
- [ ] 确认任务根目录、输出根目录、普通目录、符号链接和输出范围外路径均被拒绝。
- [ ] 传入完整输入压缩包列表，确认输入压缩包及包含它的目录不会被删除。
- [ ] 发布说明明确：`delete()` 是永久删除，不经过回收站。

说明：RAR 和 7Z 当前没有与 ZIP 等价的可靠内部内容预检查；解压后超限检查也不能避免文件先占用磁盘。这两项必须列为 RC 已知限制。

## 6. 配置测试

- [ ] 无 `config.json` 时，GameArchiveService 使用 Settings 默认值且不创建配置文件。
- [ ] 完整 config.json 能加载当前 14 个白名单字段，包括三个外部工具路径。
- [ ] 缺少字段时只对缺失项使用默认值。
- [ ] 未知字段、错误类型、负数和越界值产生 warning，但程序不崩溃。
- [ ] 显式传入 Settings 时，确认其优先级高于 config.json。
- [ ] 确认优先级为：`显式 Settings > config.json > 默认 Settings`。
- [ ] 确认 JSON 中的 `null` 能关闭文件数量或总大小限制。
- [ ] 确认字符串数字不会被静默转换为整数。
- [ ] 确认相对工具路径按 config.json 所在目录解析；删除策略和密码策略等非白名单字段会被警告并忽略。

## 7. 日志和历史检查

- [ ] 每次 GameArchiveService 任务生成一个 `task_<task_id>.log`。
- [ ] 日志包含任务开始、Task 创建、执行开始、执行完成、报告生成和历史保存成功。
- [ ] 异常日志只记录异常类型，不包含完整外部工具错误输出。
- [ ] 检查常见 `password=...`、`pwd=...`、中文密码表达和 `-p...` 参数均被脱敏。
- [ ] 默认历史文件 `%LOCALAPPDATA%\GameArchiveManager\history\task_history.json` 可以写入并重新读取。
- [ ] 默认任务日志写入 `%LOCALAPPDATA%\GameArchiveManager\logs\`，不依赖程序目录可写。
- [ ] 历史记录包含 task_id、任务路径、状态、时间、成功状态和摘要。
- [ ] 历史记录不包含密码候选、密码明文或完整敏感错误日志。
- [ ] 日志目录或历史目录不可写时，确认错误能被发现并报告。
